# TASK SPECIFICATION: Оптимизация UX и иерархии страницы «Семейное пространство» для мобильных устройств

## 1. PERSONA & ROLE
- Роль исполнителя: Senior UI/UX Engineer / Design System Architect.
- Фокус: Оптимизация вертикальной иерархии и читаемости страницы «Семейное пространство» на мобильных экранах (375px–768px): устранение дублирования списков, объединение карточек участников с аналитикой распределения трат, компактный Hero-блок бюджета и сворачиваемая форма приглашения.
- Scope Isolation: Рефакторинг `src/widgets/family-space/ui/FamilySpaceWidget.tsx` и `src/features/manage-family-membership/ui/FamilyMemberList.tsx`.

## 2. TASK & WORKFLOW
- Цель:
  1. **Компактный Hero-блок бюджета**:
     - Сделать главный акцент на доступном остатке семейных средств крупным шрифтом.
     - Интегрировать прогресс-бар расхода и компактную сетку (лимит месяца / потрачено семьей).
  2. **All-in-One карточки участников семьи (`FamilyMemberList`)**:
     - Встроить персональный прогресс-бар и процент вклада в расходы прямо в карточку каждого участника.
     - Устранить отдельный дублирующий блок «Распределение расходов», сократив высоту страницы на мобилках в 2 раза.
  3. **Сворачиваемый блок добавления участника**:
     - Заменить статичную форму на аккуратную кнопку `+ Пригласить нового участника`, раскрывающую поле ввода email при нажатии.
  4. **Справочный блок предпочтений**:
     - Разместить цели, диеты и магазины в нижнем блоке страницы.

### Алгоритм исполнения:
1. **Фаза 1: Разработка (Development Phase)**:
   - Обновить `src/features/manage-family-membership/ui/FamilyMemberList.tsx`: добавить расчет процента трат участника от общего бюджета семьи и визуальную полосу прогресса внутри карточки.
   - Обновить `src/widgets/family-space/ui/FamilySpaceWidget.tsx`:
     - Реорганизовать Hero-баннер (крупный остаток, компактные метрики).
     - Убрать дублирующий блок распределения трат (теперь он внутри карточек).
     - Добавить сворачиваемое состояние для формы добавления участника.
2. **Фаза 2: Верификация логики (Logic Testing Phase)**:
   - Проверить типы TypeScript (`npm run lint`).
   - Выполнить сборку (`npm run build`).
   - Сформировать отчеты `handoff.md` и `test-report.md`.
3. **Фаза 3: Визуальный аудит (Visual QA Phase)**:
   - Проверить верстку на брейкпоинтах (375px, 768px, 1440px).
   - Убедиться в отсутствии горизонтального скролла и перекосов.
