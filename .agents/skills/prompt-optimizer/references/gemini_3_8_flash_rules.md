# РУКОВОДСТВО И ПРАВИЛА МОДЕЛИ GEMINI 3.8 FLASH (GEMINI_3_8_FLASH_RULES.MD)

Данный документ содержит обязательные спецификации, аппаратные ограничения API и архитектурные правила промптинга для модели Gemini 3.8 Flash. Агент обязан строго руководствоваться этими правилами при анализе пользовательских запросов и генерации технических спецификаций (TASK_SPEC.md).

---

## 1. Архитектурные спецификации модели
*   **Идентификатор модели (Model ID):** `gemini-3.8-flash`.
*   **Контекстное окно (Context Window):** 1 048 576 токенов (1M).
*   **Максимальная длина вывода (Max Output Tokens):** 65 536 токенов (64k).
*   **Целевая специализация:** Сложные инженерные задачи (Long-horizon software engineering), автономные мультиагентные системы (Autonomous agents) и многоэтапное планирование.
*   **Среда исполнения:** Является базовой дефолтной моделью агента Google Antigravity.

---

## 2. Управление мышлением и рассуждениями (Thinking Levels)
В модели Gemini 3.8 Flash глубина анализа регулируется исключительно строковым перечислением `thinking_level`.

### Допустимые конфигурации:
*   `thinking_level = "low"` — минимальная задержка, подходит для простых черновых ответов, быстрых утилит и линейных правок.
*   `thinking_level = "medium"` (По умолчанию) — сбалансированный режим рассуждений, рекомендованный для проектирования кода, рефакторинга и агентных воркфлоу.
*   `thinking_level = "high"` — максимальная глубина логического анализа, предназначена для математических расчетов, отладки сложных race condition и архитектурной верификации.

### КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ:
*   Значение `minimal` категорически не поддерживается моделью Gemini 3.8 Flash. Передача `thinking_level = "minimal"` вызывает аппаратную ошибку валидации API (API validation error).

---

## 3. Запрещенные и устаревшие параметры API (Legacy Parameters)

### 3.1. Игнорируемые параметры (Backend Ignored):
Backend Gemini 3.8 Flash полностью игнорирует классические параметры сэмплирования. Их передача бессмысленна:
*   `temperature`
*   `top_p`
*   `top_k`
*   `thinking_budget` (целочисленный бюджет заменен на строковый enum `thinking_level`).

### 3.2. Запрещенные параметры (Fatal API Error):
Следующие параметры вызывают немедленный сбой запроса с генерацией ошибки API:
*   `candidate_count` (не поддерживается в семействе Gemini 3 и старше).
*   `frequency_penalty`
*   `presence_penalty`

### 3.3. Правила валидации ходов диалога:
*   Запрещены prefilled-ответы (предзаполненные ходы модели).
*   В мультиагентных конвейерах стандартизация строится через передачу идентификатора сессии или чистых артефактов без склейки сырой истории.

## 4. Синтаксические ограничения и запрет LaTeX (Syntax Guardrails)

### ПОЛНЫЙ ЗАПРЕТ LATEX:
Категорически запрещено использовать разметку LaTeX как в основном тексте, так и внутри Markdown-таблиц. Теги `\sum`, `\le`, `\ge`, `\mathcal{O}`, `\times`, `$`, `$$` нарушают синтаксический разбор и приводят к искажению отображения в веб-интерфейсах, режиме Canvas и системных дашбордах.

### Обязательные стандарты записи:
*   **Оценка алгоритмической сложности (Big-O):** оформлять строго обычным текстом в ASCII-нотации:
    - `O(1)`
    - `O(N)`
    - `O(log N)`
    - `O(N log N)`
    - `O(N + K)`
*   **Математические операторы и ограничения:**
    - Вместо `\le` писать `<=`.
    - Вместо `\ge` писать `>=`.
    - Вместо `\ne` писать `!=`.
    - Диапазоны оформлять в виде: `1 <= array.length <= 10^5`.
*   **Разделение блоков:** логические секции, директивы и списки разделять двойным переводом строки (`\n\n`) для исключения ошибок парсинга потока.

## 5. Методология промптинга: 4-Pillar Framework
Любой промпт или техническая спецификация, формируемая для Gemini 3.8 Flash, обязана структурироваться по 4 обязательным столпам:

1.  **Persona & Role:**
    - Четкое определение роли (например, Senior Fullstack Engineer, QA Automation Engineer).
    - Очерчивание предметной области и профессионального стиля (Scope Isolation).
2.  **Task & Workflow:**
    - Пошаговая декомпозиция цели на последовательные этапы (Step-by-step guidance).
    - Двухфазное разделение: планирование (Planning Phase) перед непосредственной модификацией кода.
3.  **Context & Guardrails:**
    - Технический стек проекта, архитектурные слои, используемые библиотеки и фреймворки.
    - Фиксация ограничений: `thinking_level = "medium"`, запрет на применение сторонних библиотек без согласования.
4.  **Format & Definition of Done (DoD):**
    - Формат сдачи задачи: список модифицированных файлов, прохождение статических проверок (`tsc --noEmit`), запуск автотестов.
    - **Правило чекбоксов:** в исходящей спецификации для исполнителя все пункты DoD генерируются строго пустыми (`- [ ]`), чтобы агент закрывал их по мере фактического выполнения.

---

## 6. Принцип заземления контекста (Grounding Order)
При подготовке сложных задач для Gemini 3.8 Flash соблюдать порядок размещения данных:
*   **Сначала контекст (Context First):** исходный код, структура репозитория, интерфейсы и документация размещаются в начале сообщения.
*   **Запрос и инструкции в конце (Query Last):** целевые указания, вопросы и команды формулируются в самом конце промпта с якорной связкой: *«Опираясь на приведенный выше контекст, выполни...»*.

---

## 7. Вызов инструментов и генерация функций (Function Calling)
*   **Предотвращение ошибок пре-текста:** запрещено выводить промежуточный сырой текст или рассуждения непосредственно перед телом вызова инструмента (`pre-tool commentary`).
*   **Строгое соответствие:** каждый ответ инструмента (`FunctionResponse`) обязан строго содержать парные идентификаторы `id` (или `call_id`) и оригинальное имя вызова `name`.
