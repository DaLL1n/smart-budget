# Навык: Real-Time Browser UI Tester (browser-ui-tester)

## Metadata
- **ID:** browser-ui-tester
- **Description:** Визуальный аудит верстки, адаптивности и интерактивных UX-сценариев в реальном времени с автоматическим возвратом к разработке при багах верстки.
- **Triggers:** Успешное завершение логических тестов (`test-report.md`), запрос на аудит верстки [cite: 10, 11, 15].

## Goal
Полная верификация интерфейса во встроенном Chrome. При обнаружении "сломанной" верстки, наложения элементов или белого экрана — автоматический возврат к шагу разработки [cite: 10, 68].

## Prerequisites & Tools
- Запущенный локальный сервер Vite (`npm run dev` на порту 3000) [cite: 10].
- Встроенный инструмент **`/browser`** для эмуляции Chrome [cite: 7, 10, 15].
- Файл `test-report.md` от предыдущего шага [cite: 11].

## Execution Workflow

### Фаза 1. Визуальный аудит во встроенном браузере
1. Используй команду **`/browser`** для перехода на `http://localhost:3000` [cite: 10, 15].
2. Проведи аудит адаптивности на брейкпоинтах: 375px (Mobile), 768px (Tablet), 1440px (Desktop).
3. Проверь отсутствие визуальных дефектов: наложение элементов, вылезание текста за границы контейнеров, появление горизонтальной полосы прокрутки.

### Фаза 2. Обработка UI-багов и Циклический откат (UI Loopback)
Если в процессе визуального аудита обнаружены дефекты верстки или ошибки рендеринга React:
1. **Фиксация дефекта:** Сделай скриншот проблемной области через инструмент `/browser` [cite: 10, 11] и определи CSS-селектор сломанного элемента.
2. **Создание баг-репорта:** Сформируй файл `.agent/handoff.md` [cite: 11] с тегом `[RE-RUN_DEVELOPMENT]`. Укажи в нем:
   - Описание визуального дефекта (например: *"Кнопка 'Добавить члена семьи' накладывается на форму ввода на разрешении 375px"*).
   - Путь к сохраненному скриншоту дефекта [cite: 11].
   - Ошибки из консоли разработчика в Chrome (при наличии).
3. **UI Loopback:** Останови тестирование интерфейса и верни управление агенту **`feature-developer`** для исправления CSS/верстки компонентов [cite: 68].

### Фаза 3. Завершение при успешном тесте
Если верстка стабильна и отображается без ошибок на всех разрешениях:
1. Сформируй итоговый отчет **`ui-audit-report.md`** со статусом **SUCCESS** [cite: 11, 69].
2. Удали временные файлы переноса контекста [cite: 11].

## Error Handling & Fallback (Circuit Breaker)
- **Предохранитель стилей:** Если за **3 цикла повторных исправлений** разработчик не смог исправить адаптивную сетку или наложение элементов, заблокируй автоматический конвейер [cite: 70].
- Выведи отчет со всеми скриншотами пользователю для ручной корректировки стилей Tailwind [cite: 11, 70].
