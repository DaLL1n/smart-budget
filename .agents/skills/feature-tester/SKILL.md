# Навык: QA & Verification Agent (feature-tester)

## Metadata
- **ID:** feature-tester
- **Description:** Автоматическое тестирование бизнес-логики и маршрутизация исправлений обратно разработчику при обнаружении багов.
- **Triggers:** Завершение разработки фичи, появление файла `.agent/handoff.md`, необходимость верификации логики [cite: 11, 12].

## Goal
Полная логическая верификация написанного кода. При успешном прохождении автотестов — передача задачи на визуальный UI-тест [cite: 68]. При падении тестов — автоматический откат к первому шагу разработки [cite: 68].

## Prerequisites & Tools
- Доступ к `.agent/handoff.md` и Code Diffs [cite: 11, 12].
- Тестовые фреймворки проекта (Jest, PyTest, Vitest).
- Инструмент динамической передачи управления `transfer_to_agent()` [cite: 68].

## Execution Workflow

### Фаза 1. Анализ изменений и запуск тестов
1. **Чтение Handover-контракта:** Открой `.agent/handoff.md` для получения контекста изменений [cite: 11, 69].
2. **Создание и запуск тестов:** Напиши unit- и интеграционные тесты для новой логики [cite: 14]. Запусти их в терминале (exit code 0).

### Фаза 2. Обработка ошибок и Циклический откат (Error Loopback)
Если автотесты завершились с ошибкой (**FAILED**):
1. **Локализация ошибки:** Собери логи ошибок, трассировку стека (stack trace) и выдели упавшие тестовые сценарии.
2. **Создание баг-репорта:** Перезапиши файл `.agent/handoff.md` [cite: 11], добавив в заголовок тег `[RE-RUN_DEVELOPMENT]`. Четко опиши:
   - Какие тесты упали.
   - Логи ошибок из терминала.
   - Ожидаемое поведение vs фактическое.
3. **Loopback (Возврат к началу):** Прерви текущий шаг верификации и принудительно перенаправь задачу обратно агенту **`feature-developer`** [cite: 68]. 

### Фаза 3. Передача на UI-тестирование при успехе
Если все автотесты пройдены успешно (**SUCCESS**):
1. Сформируй отчет `test-report.md` со статусом **SUCCESS** [cite: 11, 69].
2. Передай управление следующему навыку в конвейере — **`browser-ui-tester`** [cite: 68].

## Error Handling & Fallback (Circuit Breaker)
- **Предохранитель циклов (Circuit Breaker):** Во избежание бесконечного цикла правок между кодером и тестировщиком, лимит повторных итераций составляет строго **3 цикла** [cite: 70].
- На 4-й итерации прерви выполнение, заблокируй авто-исправление и выведи все логи ошибок пользователю [cite: 70].
