# КОНСТИТУЦИЯ ПРОЕКТА: СЕРВИС МОНИТОРИНГА ПРОДУКТОВОГО БЮДЖЕТА

## 1. Технологический стек и архитектура (Tech Stack)
При написании и изменении кода агент обязан использовать исключительно следующие технологии и актуальные версии:
*   **Фронтенд-ядро:** React 19.0.1, Vite 6.2.3, TypeScript (~5.8.2).
*   **Архитектурная методология:** Feature-Sliced Design (FSD) — разделение на слои `app/`, `pages/`, `widgets/`, `features/`, `entities/`, `shared/`.
*   **Управление данными и кэширование:** TanStack Query (`@tanstack/react-query` v5) с персистентным оффлайн-кэшем через `@tanstack/react-query-persist-client` и `idb-keyval` (IndexedDB).
*   **Маршрутизация:** TanStack Router (`@tanstack/react-router` v1) с типобезопасными маршрутами и централизованным `defaultErrorComponent`.
*   **Реактивное локальное состояние:** TanStack Store (`@tanstack/store`, `@tanstack/react-store`).
*   **Визуализация и графики:** TanStack Charts (`@tanstack/charts`).
*   **Стилизация:** Tailwind CSS v4.1.14 (прямая нативная интеграция через плагин `@tailwindcss/vite`).
*   **Анимации:** Motion v12.23.24 (`motion/react`).
*   **Иконки:** Lucide React (^0.546.0).
*   **Отказоустойчивость:** Двухуровневый `ErrorBoundary` (глобальный в `app/` + изолированные предохранители виджетов `QueryErrorBoundary`) с интеграцией `QueryErrorResetBoundary` и автоматической защитой от утечек информации в продакшене (`import.meta.env.DEV`).
*   **База данных и облачный бэкенд:** 
    - **Supabase** (`@supabase/supabase-js` ^2.113.0) — реляционная БД (PostgreSQL) для пользователей (`public.users`), семейных пространств (`public.families`) и расходов (`public.expenses`).
    - **Firebase** (`firebase` ^12.18.0) — авторизация пользователей (Firebase Auth) и обратная совместимость профилей (Firestore).
*   **Сетевой слой и валидация:** `axios` (^1.20.0) для HTTP-интеграций, `zod` (^4.5.4) для строгой runtime-валидации DTO и контрактов.

## 2. Локальный запуск и окружение (Dev Environment)
*   **Порт фронтенда (Vite):** Запуск строго на порту `3000` (`vite --port=3000 --host=0.0.0.0`).
*   **Скрипты:** 
    - `npm run dev` — запуск Vite-сервера разработки на порту 3000.
    - `npm run build` — сборка оптимизированного продакшен-бандла (`dist`).
    - `npm run clean` — очистка папки сборки (`dist`).
    - `npm run lint` — проверка статической типизации (`tsc --noEmit`).

## 3. Оркестрация агентов и навыки (Multi-Agent Skills)
Для выполнения задач агент должен строго переключаться между специализированными локальными навыками:
1.  **Написание кода:** Активируй навык `feature-developer` [.agent/skills/feature-developer/SKILL.md].
    *   *Дочерний навык:* `frontend-design` [.agent/skills/frontend-design/SKILL.md] (используется для верстки компонентов).
2.  **Тестирование логики и E2E:** Активируй навык `feature-tester` [.agent/skills/feature-tester/SKILL.md].
    *   *Дочерний навык:* `webapp-testing` [.agent/skills/webapp-testing/SKILL.md] (используется для Playwright & Chrome Automation).
3.  **Тестирование визуального UI:** Активируй навык `browser-ui-tester` [.agent/skills/browser-ui-tester/SKILL.md].

### Протокол последовательного конвейера разработки (Sequential Pipeline):
- **Шаг 1:** Разработчик пишет код и создает манифест передачи контекста `.agent/handoff.md`.
- **Шаг 2:** Тестировщик логики считывает манифест, пишет автотесты, запускает их и создает отчет `test-report.md`.
- **Шаг 3:** UI-тестировщик проверяет прохождение логических тестов, запускает локальный сервер Vite (`npm run dev`), открывает браузер и проверяет верстку на адаптивность, фиксируя результаты в `ui-audit-report.md`.

## 4. Алгоритм циклической самокоррекции (Self-Correction Loop)
Для обеспечения полной стабильности верстки и логики без участия человека, в конвейер внедрен протокол циклического отката и передачи багов:

```text
[feature-developer] (Пишет код) 
       │
       ▼
[feature-tester] (Тестирует логику) ───[Ошибка логики]───► Создает баг-репорт в handoff.md и передает кодеру
       │
   [SUCCESS]
       ▼
[browser-ui-tester] (Тестирует UI) ───[Ошибка верстки]───► Делает скриншот, пишет handoff.md и передает кодеру
       │
   [SUCCESS]
       ▼
 [Финал проекта]
```

### Спецификация контракта передачи багов (Loopback Contract):
Если на любом этапе верификации (`feature-tester` или `browser-ui-tester`) обнаруживается дефект, агент-тестировщик обязан:
1. Остановить выполнение текущего шага и перевести статус в `FAILED`.
2. Перезаписать файл `.agent/handoff.md`, внедрив мета-тег `[RE-RUN_DEVELOPMENT]`.
3. Описать в `.agent/handoff.md` детали ошибки:
   - Для ошибок кода: логи терминала и упавшие unit-тесты.
   - Для ошибок UI: CSS-селекторы сломанных блоков, проверяемый брейкпоинт (375px / 1440px) и путь к скриншоту.
4. Передать управление обратно агенту `feature-developer`, который перечитает файл баг-репорта, исправит код и повторно запустит конвейер тестирования.

## 5. Предохранитель от бесконечного цикла (Circuit Breaker)
Во избежание бесконечного пинг-понга правками установлен жесткий лимит: **не более 3 циклов самокоррекции**.
На 4-й итерации агент-тестировщик обязан прервать автоматическое выполнение конвейера `/goal`, зафиксировать все логи в `failed-pipeline.md` и перевести задачу в режим ожидания ручного вмешательства пользователя.

## 6. Регламент Git-воркфлоу и ограничения разработки (Constraints)
- **Изоляция кода:** Любое изменение кода должно выполняться строго в изолированном рабочем дереве или изолированной ветке. Прямые коммиты в дефолтные ветки main/master запрещены.
- **Интеграционный воркфлоу:**
  1. Инициализация через `/grill-me` (задать вопросы пользователю для снятия неопределенности).
  2. Создание артефактов Task List и Implementation Plan.
  3. Итеративное написание кода и запуск конвейера самокоррекции.

## 7. Верификация UI/UX и визуальной стабильности (Visual QA Rules)
- **Адаптивный аудит:** Агент `browser-ui-tester` обязан протестировать верстку нового меню «Семья», дашборда и раздела «Аналитика» на ключевых брейкпоинтах: 375px (Mobile), 768px (Tablet), 1024px (Laptop), 1440px (Desktop).
- **Запрещенные дефекты UI (No-Drift Check):**
  - Горизонтальный скролл на мобильной версии (375px).
  - Скачки макета (Layout Shifts) при навигации и переключении вкладок.
  - Наложение (overlap) полей ввода, кнопок и таблиц продуктового бюджета друг на друга.
  - Обрезание текста внутри блоков (text truncation) без явного CSS-правила.
